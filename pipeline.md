# Пайплайн разработки: AI-агент для поиска вакансий на HeadHunter

## 1. Постановка задачи (жёсткая спецификация)

1. По запуску скрипта открывается окно браузера.
2. Браузер переходит на главную страницу HeadHunter (`https://hh.ru`).
3. В терминале появляется запрос: **«Введите название вакансии:»**.
4. Пользователь вводит название и нажимает Enter.
5. Название автоматически вводится в строку поиска HH и отправляется поиск (клик по кнопке «Найти» или Enter).
6. После загрузки страницы результатов (появились вакансии) в контексте страницы выполняется JS-скрипт, собирающий названия и ссылки вакансий.
7. Собранные данные сохраняются в папку проекта `Vac/` (TXT + JSON).
8. В терминал выводится сообщение формата:
   `Собрано N вакансий по названию «...». Файл сформирован и загружен.`
9. Браузер остаётся открытым (закрытие вручную). Скрипт завершает работу.

## 2. Ключевое архитектурное решение

Для этой задачи **LLM не используется** — флоу детерминированный. Это устраняет прошлые проблемы:
неверные селекторы от LLM, ложные сообщения об успехе, зацикливание.
Каркас построен так, что LLM-модуль можно добавить позже отдельно.

## 5. Пошаговый сценарий main.py

1. Открыть Firefox (не headless).
2. `page.goto("https://hh.ru")`, дождаться строки поиска.
3. Обработка стартовых попапов (cookie, телефон).
4. `input("Введите название вакансии: ")` (или `--query` для авторежима).
5. `page.fill(selector, name)`.
6. **Отправка поиска через программный `form.submit()`** — клик по кнопке «Найти» и Enter на HH **не срабатывают** (события перехватываются интерфейсом). `form.submit()` — надёжный способ.
7. **Получение общего количества вакансий** — `get_total_vacancies(page)` парсит текст «Найдено N вакансий» из заголовка страницы результатов. Если не удалось определить — используется режим «все».
8. Пользователь указывает сколько скачать или нажимает Enter для всех.
9. **Сбор вакансий по страницам** — `collect_vacancies(page, max_vacancies)`: цикл переходов по страницам (`?page=N`), остановка при пустой странице, дедупликации или достижении `max_vacancies`.
10. Сохранение в `Vac/` (TXT + JSON).
11. Вывод итоговой строки. Браузер остаётся открытым (или закрывается с `--close`).

## 6. Обработка попапов

**Попап с телефоном** — приоритетный порядок закрытия:
1. `button:has-text("Продолжить без номера")`
2. `text=Позже`
3. крестик (закрывающий селектор, например `[data-qa='bloko-modal-close']`)
4. `Escape` — только как последний резерв (срабатывает не всегда).

**Cookie-баннер** — пробуем кнопку принятия/закрытия, затем Escape.

## 7. Сбор данных (JS)

Скрипт пользователя переводим в форму, возвращающую список словарей (а не `console.log`).
Добавлена фильтрация рекламных ссылок: остаются только вакансии со ссылкой, содержащей `/vacancy/`:
```js
() => {
  const nodes = document.querySelectorAll('a[data-qa="serp-item__title"]');
  const data = [];
  nodes.forEach(node => {
    if (!node.href.includes('/vacancy/')) return;  // отсекаем adsrv и прочее
    const t = node.querySelector('span[data-qa="serp-item__title-text"]');
    data.push({ title: t ? t.textContent.trim() : "Unknown", link: node.href });
  });
  return data;
}
```

## 8. Формат файлов в Vac/

**TXT** (`vacancies_<название>.txt`):
```
Собрано N вакансий по названию «название»
1. Название вакансии — https://hh.ru/vacancy/...
2. ...
```

**JSON** (`vacancies_<название>.json`):
```json
{
  "query": "название",
  "count": N,
  "vacancies": [{"title": "...", "link": "..."}]
}
```

Имя файла безопасно: символы `\/:*?"<>|` из названия вырезаются, пробелы в начале и конце обрезаются.

## 9. План автотестов

### Юнит-тесты (без браузера) — test_writer.py
1. Автоматическое создание папки `Vac`.
2. Корректность итоговой строки: «Собрано 5 вакансий по названию «Python». Файл сформирован и загружен.»
3. Корректность кириллицы в имени файла и содержимом.
4. Валидация списка словарей с ключами `title`/`link`.
5. Пустой результат (0 вакансий): файл НЕ создаётся, сообщение «Найдено 0 вакансий», без ошибки.
6. Безопасность имени файла (вырезание `\/:*?"<>|`).
7. Удаление trailing пробелов и точек из имени файла.

### Интеграционные/E2E тесты (с браузером) — test_e2e.py
1. **Навигация**: `goto hh.ru` → строка поиска видима.
2. **Поиск**: ввод «frontend» → отправка `form.submit()` → появляются `a[data-qa="serp-item__title"]`.
3. **Полнота сбора**: `test_scrape_data_full_page` — `collect_vacancies` собирает больше 20 вакансий при `max_vacancies=None`.
4. **Лимит вакансий**: `test_collect_with_limit` — `collect_vacancies(page, max_vacancies=5)` останавливается после 5 вакансий.
5. **Валидность данных**: каждая вакансия имеет `title` и ссылку с `/vacancy/`.

### Тест устойчивости
- Медленный интернет → таймауты не валят скрипт.
- Нет результатов → «Найдено 0 вакансий», файл не создаётся, без падения.
- `get_total_vacancies` не нашёл число → режим «все» без ошибки.

## 10. Риски и митигация

| Риск | Митигация |
|---|---|
| Попап с номером телефона блокирует поиск | Приоритетное закрытие по тексту кнопки, затем крестик, затем Escape |
| Автодополнение перехватывает клик | Escape + Enter как основной способ отправки |
| Карточки подгружаются позже смены URL | Ожидание `a[data-qa="serp-item__title"]` вместо `wait_for_url` |
| Изменение селекторов HH | Селекторы в константах, тесты ловят поломку |
| Кодировка кириллицы в терминале Windows | `sys.stdout.reconfigure(encoding='utf-8')` |
| LLM «врёт» об успехе | LLM убран из сценария |
| HH.ru изменил верстку заголовка количества вакансий | `get_total_vacancies` перебирает несколько селекторов, fallback на режим «все» |
